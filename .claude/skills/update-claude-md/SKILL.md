# Update CLAUDE.md

专门用于更新 `CLAUDE.md` 文件，保持项目指导文档与实际代码实现同步。

## 触发时机

当用户说以下类似话语时，此技能自动激活：
- "更新 CLAUDE.md"
- "更新 claude 文档"
- "update claudemd"
- "claude 文档过时了"

## 工作流程

### 1. 读取当前 CLAUDE.md

先读取 `CLAUDE.md` 文件，了解当前内容结构。

### 2. 检查实际代码实现

检查以下关键目录：
- `listen-vision_api/` - 后端实现
- `frontend_flutter/` - 前端实现
- `docs/` - 阶段文档

### 3. 对比并识别差异

主要检查：

| 检查项 | 当前阶段相关 |
|--------|-------------|
| **进度百分比** | Phase 1 后端/前端完成度、总进度 |
| **技术栈** | 数据库 (SQLite vs MySQL) |
| **当前阶段状态** | 迁移进度条、阶段说明 |

### 4. 执行更新

仅修改 `CLAUDE.md` 中的以下部分：

**当前项目状态** 部分：
- 更新进度条百分比
- 更新各阶段状态描述

**技术栈说明** 部分（如有变化）：
- 数据库技术更正

**后端服务** 部分：
- API 端点列表（如有新增）

### 5. 全局长期记忆 (重要！)

当用户说"添加记忆"或"记住这个"时，将以下信息添加到 CLAUDE.md：

**添加位置**：在文件末尾 `---` 分隔后添加新章节

**记忆类型**：

| 类型 | 说明 | 示例 |
|------|------|------|
| **用户偏好** | 编码风格、工作方式偏好 | "使用中文回复"、"先讲思路再给代码" |
| **项目决策** | 技术选型理由 | "选择 SQLite 而非 MySQL 因为..." |
| **重要结论** | 问题排查结果 | "B站 API 需要 WBI 签名才能调用" |
| **待办事项** | 未来需要处理的事项 | "Phase 1 完成后需要更新文档" |

**记忆格式模板**：

```markdown
---

## 长期记忆

### 用户偏好

- [日期] 偏好内容

### 项目决策记录

- [日期] 决策内容：理由

### 重要发现

- [日期] 发现内容

### 待办提醒

- [日期] 待办事项
```

### 6. 更新后确认

用对话形式简要说明修改内容，询问是否创建 git commit。

## 更新原则

1. **仅更新 CLAUDE.md** - 不修改其他文档
2. **保持结构完整** - 不删除现有章节
3. **保持双语风格** - 中文说明 + 英文技术术语
4. **简洁实用** - 移除过度设计功能的描述
5. **记忆持久化** - 重要信息记录到 CLAUDE.md 供未来会话使用

## 示例输出

```
CLAUDE.md 更新完成！

修改内容：
- Phase 1 进度: 70% → 100% (后端完成)
- 总进度: 25% → 35%
- 数据库: MySQL → SQLite
- 添加记忆: 用户偏好使用中文回复，技术术语保持英文

是否创建 git commit？
```

## 注意

- 此技能**不**修改 README.md、阶段文档或其他文件
- 如需更新所有文档，使用 `update-all-docs` 技能
- 全局长期记忆会在每次会话开始时加载，帮助保持上下文连续性
