# ListenVision 项目修整路线图与实施开发文档

本文件提供前后端统一的修整路线图与可执行实施计划，覆盖目标、阶段、任务拆分、验收标准、资源投入与风险控制。

---

## 1. 目标与范围

**前端（Flutter）**
- 优化 Provider 依赖链，降低初始化复杂度
- 解决 `build_runner` 代码生成同步问题
- 替换模板测试，补充真实用例

**后端（Node/Express）**
- 移除 SQLite 与 MySQL 错误处理逻辑不一致
- 日志脱敏（密码、Token、个人信息）
- 统一日志输出，清除 `console.log`

---

## 2. 路线图总览

| 阶段 | 优先级 | 目标 | 关键输出 |
| --- | --- | --- | --- |
| **P0** | 紧急 | 安全与基础修复 | 错误处理校准、日志脱敏、工具链一致性 |
| **P1** | 高 | 质量提升 | Provider 链重构、测试替换、API 文档同步 |
| **P2** | 中 | 自动化与持续演进 | CI/Lint 收紧、集成测试、性能评估 |

---

## 3. 分阶段实施计划

### P0：基础设施与安全修复（1–2 周）

**目标**：消除安全隐患与环境不一致问题。

**后端任务（BE）**
1. 移除 `errorHandler` 中 MySQL 错误码（SQLite 环境不匹配）
2. 日志脱敏：禁止记录密码、token 等敏感字段
3. 替换 `console.log` → 统一日志组件

**前端任务（FE）**
1. 统一 `build_runner`/Freezed 版本，消除生成冲突
2. 依赖审计，移除未使用依赖

**交付物**
- 修复后的错误处理模块
- 日志脱敏策略与实现
- 统一的代码生成流程说明

**验收标准**
- `errorHandler` 不包含 MySQL 错误码
- 日志中无明文密码/token
- `flutter pub run build_runner build` 成功无冲突

---

### P1：架构解耦与质量提升（2–4 周）

**目标**：降低耦合并建立真实测试价值。

**前端任务（FE）**
1. 重构 Provider 依赖链，目标：层级≤3
2. 替换模板 `widget_test.dart`，新增真实业务测试
3. GoRouter 路由参数与守卫规则整理

**后端任务（BE）**
1. Swagger 文档与接口行为同步
2. 控制器异常处理统一封装（不泄露底层堆栈）

**交付物**
- Provider 重构方案与实现
- 核心业务单测/集成测试
- 更新后的 API 文档

**验收标准**
- Provider 注入深度≤3
- 核心业务测试全部通过
- Swagger 文档与接口行为一致

---

### P2：持续性与自动化（4 周+）

**目标**：建立防回归机制。

**前端任务（FE）**
1. 建立 UI 集成测试（登录/搜索等关键路径）
2. Lint 规则强化（analysis_options.yaml）

**后端任务（BE）**
1. 数据访问层抽象，为未来扩展数据库预留接口
2. 限流策略压测，形成性能基准

**交付物**
- CI 检查脚本
- 代码风格指南
- 性能评估报告

**验收标准**
- Lint 无告警
- CI 自动通过
- 限流性能满足需求
